# Team Management Rules

## 팀 구성
- **Claude** (Architect): 설계, spec 작성, DB 변경, 최종 머지
- **@scout** (Developer): `spec.md` 기반 구현, 룰: `.agent/rules/scout.md` 예정
- **독립 리뷰어**: 폐기됨 (2026-09-05, 아래 §독립 보안 리뷰 참고). 필요 시 루트 CLAUDE.md 의 페르소나 리뷰만 선택적으로

## 기본 워크플로우
1. Claude가 `spec.md` 작성
2. @scout이 `spec.md` 기반으로 구현
3. 구현 전 트레이드오프·부작용 보고 → 사용자 확인 후 적용
4. (선택) 페르소나 리뷰 반영 후 머지

## 에이전트 호출 가이드

**@scout 호출 시 포함할 것:**
- `spec.md` 또는 구체적 작업 지시
- 수정 대상 파일 경로
- 관련 DB 함수/스키마 요약 (필요 시)

**독립 리뷰 요청 시 포함할 것:**
- 변경된 코드 전문 (또는 diff)
- 변경 배경 및 목적
- 리뷰 관점 명시: 보안 / 인증 로직 / DB 설계 / 실용성

**병렬 리뷰 패턴** (대형 작업):
- 섹션 A: DB·RLS·RPC 보안
- 섹션 B: 프론트엔드 로직·UX
- 섹션 C: 성능·코드 품질

## 역할 경계
- DB 스키마/함수/RLS 변경 → **Claude만** (MCP 도구 사용)
- 프론트엔드 구현 → @scout에게 위임 가능
- Claude가 직접 구현할 경우 spec.md 생략 가능

## 독립 보안 리뷰 — 폐기 (2026-09-05)

아래 트리거 기준은 1년 전 정책이며 **더 이상 적용하지 않는다** (사용자 결정, 2026-09-05).
DB·RLS·RPC·인증 변경 시에도 별도 독립 리뷰어(fresh Claude/codex)를 자동으로 붙이지 않는다.
대신 구현 전에 **예상 트레이드오프·부작용을 먼저 찾아 보고**하고, 사용자가 필요하다고 할 때만
루트 CLAUDE.md 의 페르소나 리뷰(`gemini --persona=security` 등)를 소프트 제안한다.

# 홈페이지 정합성 수정 — 운영 적용 완료

사용자의 운영 DB 변경 승인 후 2026-09-08 Supabase MCP로 `20260908_homepage_integrity.sql`을 적용했다. 운영 migration은 `20260908022922_homepage_integrity_20260908`이다. 연결 URL과 로컬 프로젝트 일치를 확인했으며, `npm run pull-schema`로 `_LIVE` 스냅샷을 동기화했다.

## 수정 내용

- 인기 게임 RPC의 공개 게임 정보·조회수 집계만 anon에게 허용한다. 테이블 쓰기, 개인정보 조회 권한은 추가하지 않는다.
- 키오스크 반납은 게임 → 정확한 대여 행 순서로 잠그고, 상태·기한·실제 대여자를 다시 확인한다. 기한 내 회원 반납만 50P를 받는다. 연체·비회원은 0P, 반복 요청은 변경 없이 실패한다. 반환 JSON의 `points_awarded`를 화면에 합산한다.
- 기존 RPC 인자·응답의 `success`는 유지한다. `p_user_id`는 호환용으로만 남긴다. `rental_id`를 생략하면 다른 대여를 임의로 고르지 않고 실패한다. 현재 저장소의 호출은 모두 정확한 ID를 전달한다. 외부/오래된 클라이언트도 ID를 전달하는지 적용 전에 확인한다.
- `point_transactions.created_at`과 `matches.played_at` 기본값을 `now()`로 바꾸어 UTC/KST 세션 모두 같은 실제 시각을 저장한다.
- INSERT 또는 대여 종류·대여 시각·반납 시각 변경 시 트리거로 실제 대여의 시간 역전을 막는다. 종료된 RENT는 대여 시각이 필수이며 반납 시각이 그보다 빨라서는 안 된다. 미리 잡은 HOLD나 종료된 DIBS는 이 규칙에 포함하지 않는다.

## 기존 기록은 별도 확인 필요

2026-09-08 연결 확인 후 읽기 전용 조회에서 실제 대여의 반납 시각 역전 **10건**과 두 KST 기본값을 확인했다. 실제 대여/반납 시각의 정본이 없으므로 날짜를 서로 바꾸거나 일괄 9시간 차감하지 않았다. 과거 포인트·매치 시각도 명시적 입력인지 기본값인지 저장된 행만으로 구분할 수 없다. 과거 연체 보상을 회수하려면 해당 포인트 거래와 대여의 정확한 연결 및 운영 승인이 필요하다.

트리거는 기존 잘못된 기록을 소급 수정하거나 migration을 막지 않는다. 탈퇴 처리의 사용자 ID 익명화 등 시간·종류와 무관한 수정은 허용한다. SQL의 SET 목록에 시각 필드가 있어도 값이 실제로 바뀌지 않으면 허용한다. 시간·종류를 실제로 바꿀 때에는 변경 후 기록이 정상이어야 한다. 원본 근거가 확보되면 정확한 시각으로 정정할 수 있다.

`20260908_homepage_integrity_verify.sql`은 기본값·권한·트리거·이상 건수를 개인정보 없이 검증하는 읽기 전용 SQL이다. 새 로그 기반 연체 보상 집계는 과거 로그의 복구 근거로 사용하지 않는다. 반납 후 기한을 관리자가 수정하면 이 집계도 달라질 수 있다.

## 검증과 적용 순서

`npx vitest run tests/database.test.js tests/databaseReturnModal.test.jsx`는 운영과 무관한 PGlite PostgreSQL 및 모의 API 화면에서 실행한다. 대여/포인트 fixture는 메모리에만 있다. 실제 운영 RLS 전체·다중 세션 동시성은 이 테스트 범위가 아니며, 운영에서 테스트 데이터를 생성하지 않았다.

수정한 화면은 구 서버가 `points_awarded`를 생략해도 반납 완료만 표시하여 임의의 지급액을 주장하지 않는다. 운영 자격증명·테스트 데이터 생성·과거 포인트 회수는 수행하지 않았다.

## 운영 적용 검증 결과

- 로컬 DB·반납 화면 테스트: 13개 통과.
- 비로그인 실제 REST 인기 순위 호출: HTTP 200, 20개, 공개 게임 필드와 집계만 반환.
- 두 시각 기본값: `now()` 확인. 반납 기한 검사와 시간 순서 트리거 설치 확인.
- `kiosk_return`: anon 실행 불가, authenticated 실행 가능, 함수 내부 역할 검사 유지. `earn_points` 직접 실행 차단과 정책 평가용 권한 함수의 anon 실행 권한 유지.
- anon 테이블 쓰기 권한 0건, 재고 불일치 0건. 과거 반납 시각 역전 10건은 변경하지 않음.
- 스키마 동기화: 함수 91개, 테이블 20개, 정책 44개, Enum 1개.
- Security Advisor: 인기 순위의 의도된 공개 실행 때문에 anon SECURITY DEFINER 알림이 8개에서 9개로 증가. 기존 로그인 역할의 함수 실행 알림 65개, 정책 없는 RLS 테이블 알림 1개, 유출 비밀번호 차단 비활성 알림 1개는 유지된다. 비밀번호 초기화 정책은 사용자의 요청대로 유지했다.

배포된 키오스크 JS가 정확한 `rental_id`를 전달하는 것을 확인했다. 현재 배포 화면에는 성공 시 무조건 건당 50P라고 표시하는 기존 문구가 남아 있다. 서버의 실제 지급은 수정됐지만 표시를 맞추려면 로컬 화면 코드의 별도 배포가 필요하다. 이번 작업에서는 프런트엔드를 배포하지 않았다. 운영 대여·포인트 행을 생성하거나 실제 반납을 수행하는 검증은 하지 않았다.
